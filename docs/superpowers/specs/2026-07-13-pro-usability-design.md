# 专业可用性优化：诚实口径 + 组合动线 + 反馈降级（2026-07-13）

## 背景：12 个月回放的真相

回放（run 20260713-091616，2025-05-30 ~ 2026-06-18，52 期 × top20，T+5 对全市场中位）完成后的审计发现：

| 口径 | pattern 池 | smart 池 |
|---|---|---|
| 平均超额（as_of 收盘入场） | +2.00% | +1.17% |
| **中位超额** | **-0.45%** | **-0.23%** |
| 超额胜率 | 48.6% | 47.4% |
| as_of 收盘已近涨停（买不到回测价） | **64.1%** | 1.8% |
| 平均超额（次日开盘可成交口径） | +1.74% | +1.37% |
| 次日开盘口径中位 / 胜率 | -0.52% / 48.2% | -0.03% / 49.6% |

三个结论：

1. **策略有超额，但只在组合层面**：均值为正全靠右尾（单期 top20 里几只大肉股扛起整池），单票是接近抛硬币、中位略输的游戏。用户单买一两只，大概率体验为亏。
2. **pattern 池 64% 的票收盘已近涨停**，回测价买不到；但次日开盘口径下均值仍 +1.74%，超额不是涨停幻觉，只是入场价必须诚实。
3. 近 30 天实盘留痕超额为负（smart T+5 -5.6%）与回放为正并存：弱市期（近5日全市场中位 -3.7%）+ 小样本 + 口径差异。不回避，两组数据并排给用户。

产品含义：**必须把「整池等权买入」变成一键动作，把「单票中位为负」的真相印在页面上**——这是与拍脑袋荐股产品的本质区别，也是专业用户信任的来源。

## 实机走查发现（2026-07-13 盘前~盘中）

- P0 `GET /api/quant/signal-stats` 单次 **19.9 秒**（每次全量重算 90 天留痕评估），理由卡抽屉「历史表现」形同挂死。
- P0 短线波段模式弱市只剩 1 只达标（swing_pool min_score=60 硬阈值），UI 无解释，步骤文案却写「筛出前 20 只」——用户以为产品坏了。
- P1 后端重启窗口期，前端把 `Request failed with status code 500` 裸串甩给用户，无降级文案、无重试。
- P1 「重跑回放（约 10 分钟）」重操作无确认弹窗（本人走查时误触发全量重扫）。
- P1 复盘留痕明细出现同日同池重复名次（11、11、13、13…），疑似当日多次扫描重复入库污染统计。
- P2 智能选股「推荐 N 只」与留痕条数口径不一致；盘前「今日」页宏观条新旧数据混排（指数为实时、涨跌家数为上一交易日）。
- 已顺手修复：回放会话轴锚定「今天」导致跨天续跑 param_key 漂移、4900 断点作废（run_replay 加 anchor 参数，resume cron 传原 run 锚定日；测试 test_replay_anchor_pins_session_axis）。

## 竞品参照

果仁网（专业标杆）的可信度支柱恰是本轮方向：组合级回测（非单票口径）、消除未来函数/存活偏差的诚实口径、策略→组合→跟踪闭环、业绩分析对基准。stockgod 类展示层功能上一轮已借鉴完毕。

## 目标

1. 回放/复盘的每个数字都可成交、可解释（次日开盘口径、中位数、涨停占比标注）。
2. 「整池等权买入」一键完成，组合页可对照全市场基准。
3. 重要接口秒开；错误反馈引导行动；重操作有确认。

## 非目标

- 不改选股规则本身（评分公式、阈值取值）——规则迭代基于本轮口径数据另行立项。
- 不做实盘交易接口；不承诺胜率。
- 不动「今日」页宏观条新旧混排（P2，收益小改动面大）。
- 回放不建模调仓换手成本（模拟组合已含真实成本，两者定位不同并注明）。

## 批次设计

### 批次 A：回放诚实口径（次日开盘入场 + 分布统计）

- `replay_results` 增列 `ret_t5_open` / `excess_t5_open`（entry=as_of 次一交易日开盘价，exit=T+5 收盘；基准=全市场同窗口 open(d1)→close(d5) 中位；开盘价缺失/为 0 记 null）。
- `replay_results` 增列 `limitup_at_close`（as_of 当日 close/prev_close-1 ≥ 9.5% 即 1）。
- `_summarize` 每池增加：`median_excess`、`p10`/`p90`、`limitup_ratio`，以及 `open_entry` 子块（mean/median/win_rate）。
- 老数据兼容：`ALTER TABLE ... ADD COLUMN`（幂等 try/except），旧 run 新列为 null，summary 对 null 容错。
- 前端 Review「历史回放」区：双口径切换（回测口径 / 次日开盘可成交口径），涨停占比标注，中位数与均值并排。
- **结论卡**：回放区顶部一句人话结论，由数据模板生成（如「过去 12 个月每期等权买入整池：平均超额 +1.7%/期（可成交口径），但单票中位 -0.5%、胜率 48%——收益依赖整池分散，不适合单票押注」）。规则：mean>0 且 median<0 → 组合依赖提示；mean≤0 → 直接判无效。
- 测试：构造已知开盘/收盘矩阵验证 open 口径计算、涨停标记、median/p10/p90。

### 批次 B：signal-stats 缓存（19.9s → 秒开）

- `signal_stats` 结果按 `(pool, pattern, 最新完整交易日)` 缓存进 SQLite 表 `signal_stats_cache`（key, as_of, payload_json, created_at），命中直接返回；当日已有缓存不重算。
- 15:40 结算 cron 完成后主动失效当日 key 并预热常用 pool（pattern/smart/swing/auction 各一次，后台线程）。
- 理由卡抽屉「历史表现」加载超 3s 显示「首次统计约需 20 秒，稍后自动就绪」（后端预热后一般命中缓存）。
- 测试：两次调用第二次走缓存（打桩计数）；跨日失效。

### 批次 C：选股页动线（坍缩解释 + 一键跟池 + 留痕去重）

- **坍缩解释**：swing/smart 结果不足 5 只时，结果区显示「当前市场环境达标标的仅 N 只（阈值 60 分）」提示条 + 大盘环境标签联动；步骤文案「筛出前 20 只」改为「筛出达标候选（上限 20）」。不放宽阈值、不加观察名单（保持口径诚实、避免留痕污染）。
- **一键跟池**：
  - 后端 `POST /api/quant/portfolio/add-batch`：body 传 `[{symbol, name, price}]` + `budget_per_stock`（默认 1 万），复用现有单笔加入逻辑（整手、A 股成本），返回逐笔成交/跳过原因（不足一手/价格缺失/已持有）。
  - 前端智能/形态结果表头部「整池加入组合」按钮 → 确认弹窗（列出票数、每票预算、预计总金额）→ 调批量接口 → 汇总提示（成交 X 跳过 Y，跳过原因可见）。
  - 组合页来源标注池名。
- **留痕去重**：`record_picks` 改为同 (pick_date, pool, symbol) UPSERT（保留最新评分/名次）；评估端按同键去重兜底存量脏数据。测试：同日双扫描同股只留一条。

### 批次 D：反馈与降级

- 前端 `ApiClient` 统一拦截：网络错误/5xx → 统一提示「服务暂时不可用，正在自动重试…」，幂等 GET 自动重试 1 次（2s 退避）后仍失败显示「稍后重试」引导；不再裸抛 status code 串。
- 「重跑回放」加 `ElMessageBox.confirm`（说明耗时约 10 分钟、CPU 占用、结果覆盖时间轴）。
- 测试：vue-tsc + 构建通过；Playwright 断言拦截器文案存在（打桩 500）可选。

### 批次 E：有效性结论报告 + 收尾

- `docs/superpowers/specs/2026-07-13-replay-validation-report.md`：三池结论（有效/无效/存疑）、双口径全表、月度分布、与实盘留痕差异的解释、局限（存活偏差/近似口径/无换手成本）。
- README 功能清单同步；侧边栏分组（看盘/选股/验证跟踪/系统，纯 el-menu-group 不改路由）。

## 共性约定

- 外部数据 float 一律 `x == x` 判 NaN 再入 JSON；ALTER TABLE 幂等；长任务防重入不变。
- 每批次：pytest 全绿 + vue-tsc/vite 构建 + headless Playwright 实机巡检对应页面。

## 验证标准

- 回放页可见双口径与结论卡（真实数据渲染）。
- signal-stats 二次调用 < 1s。
- 整池加入组合端到端成功（真实价格、整手、确认弹窗、组合页可见来源）。
- swing 坍缩时提示条出现；留痕当日无重复；5xx 有友好提示。
