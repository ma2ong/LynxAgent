# 集合竞价买入推荐：验证报告与降级决定

**日期**：2026-09-09
**结论**：竞价「买入推荐」在可交易口径下没有 alpha，匹配对照增量为负。功能降级为
「竞价异动观察」，下线推荐档位、综合强度分与名次徽标。选股与留痕逻辑不动。

---

## 起因

Allen：「感觉集合竞价的质量越来越差了，推荐的都是负收益的。」

当天页面上的 5 只，竞价高开 +5.67% ~ +8.87%，全部标着「最强推荐 / 强推荐」，
盘中全部翻绿。查下来不是最近变差——是从一开始就没有过正收益。

## 三份互相独立的证据

### ① 线上留痕（46 个交易日 / 601 条，2026-07-02 ~ 09-08）

买点取当日开盘价（= 09:25 竞价撮合价），超额相对全市场同口径均值。

| | 盘中超额 | T+1 超额 | 胜率(T+1) |
|---|---|---|---|
| 页面展示的前 5 名 | −0.43pp | −0.68pp | 42.6% |
| 压着没展示的 6-15 名 | +0.29pp | +0.10pp | 48.1% |

**展示出去的比没展示的更差。** 当日涨停率：第 4-5 名 5.7%，第 6-15 名 9.6%。

排序本身没有预测力：当日「分数名次 vs 当日实际收益名次」的 Spearman
**rho = −0.005**（t = −0.12，41 天）。评分公式
`高开×6 + 量比×8 + 板块共振×1.8 + 板块趋势×0.6` 对「今天这几只里哪只更强」
不含信息。「最强推荐」四个字背后是空的。

按月看确实在恶化（7 月 +0.75pp → 8 月 +0.17pp → 9 月 −1.98pp），但那是雪上加霜，
不是病因。

### ② rule_audit.py 七道闸

```bash
python experiments/rule_audit.py --pool auction --entry open0 --horizon 1
```

| 卖点 | 超额 | 去右尾 | 匹配对照增量 | CI 下沿 | 判定 |
|---|---|---|---|---|---|
| 当日收盘（不可交易） | −0.06 | −0.11 | **−0.81** | −1.48 | 未过 |
| T+1 收盘 | −0.15 | −0.24 | **−0.60** | −1.37 | 未过 |

第 3 关（匹配对照）是这套尺子的核心：跟**同一天、同样跌幅档、同样流动性档、
但没上榜**的票比，上榜的这批反而更差。不是"没用"，是负贡献。

### ③ 12 个月全市场回测（干净口径）

```bash
python experiments/auction_tradeable_ab.py --months 12
```

线上现行规则在四个卖点上：

| 卖点 | 样本内 | 样本外 |
|---|---|---|
| 当日收盘（不可交易） | −0.286 (t=−1.01) | −0.218 (t=−0.53) |

| T+1 收盘 | −0.243 (t=−0.61) | +0.679 (t=1.12) |
| T+2 收盘 | −0.259 (t=−0.60) | +0.217 (t=0.33) |

试过的四种修法（高开上限收到 5% / 收到 4% / 改取最温和的高开 / 竞价情绪弱时空仓）
无一显著。按高开幅度分档，没有任何一档为正。

## 立项证据是假的

`experiments/results/auction_rule.json` 里 `A_current = +0.438pp / t=2.57` 是这个功能
上线的依据。它有两处口径问题，各自都会把数字抬上去：

1. **候选用当日全天成交额筛**（`amt < MIN_AMOUNT`）。09:25 决策时这个数不存在——
   等于先知道哪些票今天会放量，再回头挑它们。
2. **组合取均值、基准取中位**。个股收益右偏，实测全市场均值比中位高
   +0.134pp/日（盘中）、+0.196pp/日（T+1），这部分与选股能力无关。

两处都改掉后，同一条规则是 **−0.33pp**。已在 `experiments/auction_rule.py` 头部标注，
文件保留不删——它是 2026-07-28 那次决策的现场记录。

## 一个真实但吃不到的信号

顺手扫了从没试过的另一侧：买**低开最深、但昨收仍在 MA20 上方**的票。

| 卖点 | 样本内 | 样本外 |
|---|---|---|
| 当日收盘 | +1.398pp, t=5.76 | **+2.141pp, t=5.86, 胜率 74.7%** |
| T+1 开盘 | −0.794pp | −0.764pp |
| T+1 收盘 | −0.226pp | +0.038pp |

样本外能复现、t 接近 6，是真实的日内反转。两个理由让它无法变成产品：

1. **A 股 T+1**，当日买入最早次日才能卖，而这份超额在**次日开盘前被完全抹平**；
2. 就算能卖，它多半是 beta 不是 alpha——「深跌的票本来就比全市场反弹得多」，
   这里的基准是同范围均值，没做跌幅档匹配对照。

记录在案，免得下次有人重新想起「要不要反着做」时再扫一遍。

## 落地的改动

**下线（`quantcore/quant/call_auction.py`）**

- 推荐档位 `最强推荐 / 强推荐 / 推荐` 及其弱势日相对措辞（`TIER_NAMES*`、
  `TOP_TIER_RATIO`、`STRONG_TIER_RATIO`、`ABS_STRONG_OPEN_PCT`、`tier_note`、
  `relative_only`、`strong_tier_count`）
- 综合强度分 `strength`、名次 `rank`
- 输出键 `buy_candidates` → `watch_candidates`

**不动**

选股条件、评分公式、排序、留痕（`record_picks("auction", ...)`）全部原样。改了就要
换池名，46 天样本会断档，而这条规则恰恰需要继续被观测——用一次结论把观测关掉，
就再也回答不了「换个市场环境它会不会变」。

**改文案**

- `hit_stats` 从过期的 18 天 / 314 条更新为实测 46 天 / 601 条，并补上匹配对照增量
  与 Spearman；
- 卡片首行直接写「这不是买入清单」和三个负数；
- 「较竞价 −1.55%」改成「盘中较竞价」，并在 title 里写明 A 股 T+1 当日无法卖出、
  该数不可兑现。原措辞拿一个用户兑现不了的数字天天报负值，既不准确也没意义。

**回归守卫**

`tests/test_call_auction_limit.py::test_no_recommendation_packaging_leaks_back`——
名次 / 档位 / 强度分不许再出现在名单里。哪天有人凭手感加回来，先被这条拦一次。
